# 2608121003 - AGP 9.3.0 / Gradle 9.5.0 升級

- Created: 2026-08-12 / Archived: 2026-08-20
- Issue: N/A（歸檔時複核：本 repo 的 GitHub Issues **實為啟用中**，當時的「已停用」判定有誤，見 Deviations）

## Summary

Android 建置工具鏈由 AGP 8.13.x / Gradle 8.13 升至 **AGP 9.3.0 / Gradle 9.5.0**，目標版本一次達成、未觸發退版。
動機是讓本 fork 的 Android 建置離開即將被 Flutter 淘汰的工具鏈區間。實際只需移除一個在 AGP 9.0 被**移除**（非棄用）
的選項 `android.defaults.buildfeatures.buildconfig`，Kotlin 維持 2.2.20 未動以縮小 delta。
影響範圍限於兩個 example 的 Gradle 設定與 `flutter_inappwebview_android` 的 `android/build.gradle`，無任何行為變更。
後續由計畫 2608151157 證實：Flutter 3.47 把該相容分支的 Gradle 下限提高到 9.3.1，此次升到 9.5.0 剛好接住。

## Cross-Repo Scope

無（單一 repo）。

## Key Decisions

- **目標訂為 AGP 9.3.0 / Gradle 9.5.0**（使用者指定）。已於提出時揭露它超出 Flutter 3.44.8 驗證範圍三個小版本；
  `gradle_utils.dart` 對「比已知版本新」的 AGP 採放行策略，故版本檢查會通過。
- **範圍含已棄用寫法清理**（使用者指定）：`lintOptions`→`lint`、`minSdkVersion`→`minSdk`、
  `compileSdkVersion`/`targetSdkVersion`→`compileSdk`/`targetSdk`。
- **先把軟鍵盤分支併入 `main` 再開工**（Q1）。理由：`main` 上的 example 因 Jetifier 記憶體不足本來就建不起來，
  沒有可建置的基準就無法歸因升級失敗。代價是 `main` 上多了一個當時尚未完成驗證的功能。
- **失敗時自動退到 AGP 9.0.1 + Gradle 9.1.0**（Q2）。理由：那是 `flutter create` 產生、已知能建置本套件的組合。
  **實際未觸發**。
- **Kotlin 不升級**（B3）。2.2.20 在 AGP 9.3.0 下建置通過，維持原值以縮小 delta。
- **`android.nonTransitiveRClass` 與 `android.nonFinalResIds` 刻意保留**（C5）。兩者是**行為旗標**而非語法，
  移除等於改用新預設，屬行為變更，超出「只做工具鏈升級」的宣告。

## Deviations

- **階段順序在執行中被實測修正**：原把「已棄用寫法清理」排在 AGP 升級之後。實際上
  `android.defaults.buildfeatures.buildconfig` 在 AGP 9.0 已被移除，AGP 9.3 於載入 plugin 階段即拋錯，
  連編譯都到不了——該項清理是升級的**前置條件**。移除前已確認全 repo 無任何程式碼使用 `BuildConfig`。
- **C4 偏離「逐項驗證」紀律**：五處棄用寫法一次改完未逐項建置。理由是 AGP 9 的錯誤訊息會精確指名出問題的
  DSL 元素，歸因不依賴變更隔離，而每輪建置約 7 分鐘。結果通過，未出現需要退回逐項驗證的模糊錯誤。
- **C5 未結清**（見 Key Decisions，刻意保留）。
- **E1 `git diff upstream/master` 的 delta 檢查未執行**；E2 的 PR 目標 repo 確認亦無紀錄。
- **Issue 追蹤基準判定錯誤**：計畫記載「本 repo 為 fork，GitHub Issues 已停用」，
  但 2026-08-15 以 `gh repo view --json hasIssuesEnabled` 複核為 `true`。此錯誤前提影響了本計畫與
  2608121440，兩者皆未綁定 issue；自 2608151157 起已改正。

## Details

**驗證數據**（Flutter 3.44.8 / Java 22.0.2 時期）：升級前基準 debug 593.0s；升級後 428.0s（`flutter_inappwebview/example`）、
80.4s（`flutter_inappwebview_android/example`），皆 `EXIT=0`。兩者快取狀態不同，此數字**不足以宣稱**升級改善建置速度。
`flutter build apk --release` 通過（367.4s，67.4MB），走完 R8／minify——套件的 `release` 開著 `minifyEnabled true`
並帶 `consumerProguardFiles`，是大版本升級最易出事之處，debug 完全不經過。實機執行無 FATAL。

**當時記錄、後續才處理的警告**：Flutter 警告 app 與 `file_picker`／`flutter_downloader` 套用了 Kotlin Gradle Plugin，
未來版本將因此建置失敗，建議遷移至 Built-in Kotlin。此為 Flutter 的破壞性變更預告，與 AGP 9 無關；
計畫 2608151157 再次確認後同樣決定不處理（本套件為純 Java、不 apply KGP，不在被點名之列）。
